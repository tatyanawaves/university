# University в Unreal Engine 5.8: подключение и план переноса

Из веб-версии (`universe/`) переносим **механику и данные**, но не внешний вид.
Картинку строим заново средствами UE: Lumen, Nanite, Sky Atmosphere,
Volumetric Clouds, Niagara, PCG.

## 1. Подключение Claude Code к редактору (Unreal MCP)

По [документации Epic](https://dev.epicgames.com/documentation/unreal-engine/unreal-mcp-in-unreal-editor):

1. **Edit → Plugins**: включить **Unreal MCP** (`ModelContextProtocol`) и **All Toolsets**
   (он включит Toolset Registry). Перезапустить редактор.
2. **Edit → Editor Preferences → General → Model Context Protocol**: включить
   **Auto Start Server**. Порт `8000` и путь `/mcp` оставить по умолчанию,
   **Enable Tool Search** оставить включённым: так Claude подгружает схемы
   инструментов по запросу и не тратит на них токены заранее.
3. Конфиг клиента уже лежит в корне репозитория (`.mcp.json`):
   ```json
   { "mcpServers": { "unreal-mcp": { "type": "http", "url": "http://127.0.0.1:8000/mcp" } } }
   ```
   Тот же файл создаёт консольная команда редактора
   `ModelContextProtocol.GenerateClientConfig ClaudeCode`.
4. Запустить Claude Code **на том же компьютере**, где открыт редактор, из корня
   репозитория (`claude`), подтвердить сервер `unreal-mcp` из `.mcp.json`.
   Проверка: `claude mcp list` должен показать `unreal-mcp … connected`, а `/mcp`
   внутри сессии покажет его инструменты (`SceneTools`, `ActorTools`,
   `MaterialInstanceTools`, `ObjectTools`).

> **Важно.** Сервер слушает только `127.0.0.1` и отвергает запросы с чужим
> `Origin`, авторизации у него нет. Облачная сессия Claude Code (claude.ai/code)
> работает в удалённом контейнере, и её `127.0.0.1` — не ваш компьютер.
> Поэтому подключаться к редактору нужно из **локального** Claude Code
> (терминал, VS Code/JetBrains или десктопное приложение). Пробрасывать порт
> наружу через туннель не стоит: без авторизации любой, кто найдёт URL,
> получит управление редактором.

## 2. Как тратить меньше токенов

Главный принцип: **Claude пишет генераторы, а миры строит игра.** Если
строить планету через MCP по одному актору, каждый вызов инструмента и его
JSON-ответ оплачиваются токенами, а результат нельзя воспроизвести. Если же
написать генератор один раз, каждый следующий мир стоит ноль токенов.

| Задача | Дорого | Дёшево |
|---|---|---|
| Планета, астероиды, растительность | расставлять акторы через `ActorTools` | PCG-граф + C++-генератор по сиду; MCP только проверяет результат |
| Материалы миров | вручную настраивать каждый в чате | один мастер-материал + DataAsset с параметрами из `universe/worlds.ts` |
| Реальные звёзды и экзопланеты | просить Claude «рассказать» о системах | CSV-каталог → DataTable (скрипт ниже, запускается без модели) |
| Проверка сцены | полный дамп сцены, скриншот на каждый шаг | запросы по классу или метке, скриншот только в конце |
| Реплики существ | вызов LLM на каждую реплику | грамматика + банк реплик, LLM по желанию (раздел 6) |

Правила для Claude при работе с редактором записаны в `unreal/CLAUDE.md`.

## 3. Что и куда переносится

Проект UE предлагается держать в `unreal/UniverseUE/` (C++-проект, для
`.uasset` понадобится Git LFS). Логика переносится в C++ модуль за модулем,
с теми же сидами (`mulberry32`, `hash32` из `universe/mandelbrot.ts`), чтобы
одинаковые сиды давали одинаковые системы в вебе и в UE.

| Веб (`universe/`) | UE 5.8 |
|---|---|
| `physics.ts`: Кеплер, орбиты, периоды | `UOrbitLibrary` (C++, чистые функции) + Automation-тесты, те же, что в `test/` |
| `mandelbrot.ts`: галактики и системы из множества Мандельброта | `FUniverseGenerator` (C++), 1:1 по алгоритмам |
| `solarSystem.ts`: элементы JPL | DataTable `SolarSystem` |
| `atmosphere.ts`: коэффициенты Рэлея и Ми | напрямую в `SkyAtmosphereComponent` (там те же физические параметры) + Volumetric Clouds |
| `worlds.ts`, `planetShaders.ts`: материалы поверхностей | мастер-материал планеты + Material Instances по `FEATURE` (io, europa, mars…) |
| `terrain.ts`, `levels/planet.ts`, `game/surface.ts`, `game/scatter.ts` | посадка = отдельный уровень, как сейчас: Landscape из того же шума + PCG (камни, растения, строения) |
| `levels/galaxy.ts`, `levels/cosmicWeb.ts` | Niagara (GPU-частицы) для звёзд и нитей паутины |
| `levels/blackHole.ts` | пост-процесс-материал: GLSL-трассировка переносится в HLSL Custom node |
| `flight.ts`, `game/shipGame.ts` | Pawn корабля, Enhanced Input, автопилот как компонент |
| `game/combat.ts`, `game/missions.ts`, `game/progress.ts` | подсистемы `UGameInstanceSubsystem`, `USaveGame` |
| `game/creatures.ts`, `game/surfaceLife.ts`, `game/robot.ts`, `game/vehicle.ts` | Character/Pawn, ИИ на StateTree, ровер на Chaos Vehicles |
| `game/dialogue.ts` | `UDialogueSubsystem` + HTTP-модуль, UI на CommonUI/UMG |
| `game/menu.ts` | UMG |

Большие расстояния: в UE5 включены Large World Coordinates (double). Для
масштабов системы всё равно понадобятся масштабирование и сдвиг начала
координат вокруг корабля, как в вебе.

## 4. Порталы: случайные миры или настоящая Вселенная

**Возможно ли и сколько стоит:** да, и в игре на это не тратится ни одного
токена. Генерация идёт в рантайме по сиду, а реальные данные лежат
локальной таблицей. Токены уходят только на то, чтобы один раз написать генератор.

Сейчас порталы уже детерминированы по сиду системы (`portalSpecs()` в
`universe/levels/starSystem.ts`): звезда этой галактики, другая галактика,
чёрная дыра, дом. Предлагается три режима на выбор при входе в портал:

1. **Случайный мир.** Сид = `hash32(сид системы, номер портала, счётчик прыжков)`.
   Из него `FUniverseGenerator` выводит звезду (спектральный класс → цвет и
   яркость), планеты (тип, атмосфера, материал по `FEATURE`), биом для PCG.
   Мир каждый раз новый, но по сиду его можно повторить, сохранить или
   поделиться им.
2. **Настоящая система.** Портал ведёт к реальной звезде из каталога
   экзопланет NASA: `unreal/Data/RealStars.csv` (4779 звёзд с расстоянием,
   координатами, температурой, массой и радиусом) и `RealPlanets.csv`
   (6372 подтверждённых планеты с полуосью, эксцентриситетом, периодом,
   радиусом, массой и равновесной температурой). Чего наблюдения не дают
   (цвет поверхности, облака, рельеф), генератор досоздаёт из физики:
   равновесная температура и масса определяют тип мира (лава, лёд, газовый
   гигант, суперземля), а сид — детали. Так Proxima Cen b выглядит
   правдоподобно и каждый раз одинаково.
3. **Смешанный (рекомендую).** Ближние порталы ведут к реальным системам,
   дальние («в другую галактику») — к генерируемым: реальных данных там нет.

Каталог обновляется командой
```bash
python3 unreal/Tools/build_catalog.py
```
Она без ключей обращается к публичному TAP-сервису NASA Exoplanet Archive.
Звёздное небо тоже можно сделать настоящим: HYG Database (≈120 тыс. звёзд)
запекается в кубическую карту или Niagara-систему с настоящими положениями
и цветами звёзд.

## 5. Внешний вид: красочно и реалистично

- **Космос.** Небо из реальных звёзд (HYG) с цветом по температуре, полоса
  Млечного Пути, туманности как объёмные материалы (Heterogeneous Volumes),
  автоэкспозиция и bloom, чтобы звезда слепила, а тень планеты была
  по-настоящему чёрной. Галактики и паутина на Niagara.
- **Планеты с орбиты.** Sky Atmosphere с параметрами из `atmosphere.ts`,
  Volumetric Clouds, океаны с отражением, ночная сторона с огнями городов
  у населённых миров, кольца полупрозрачным материалом с тенью от планеты.
- **Поверхность.** Landscape + Nanite-камни, PCG-биомы (пустыня, лёд, лава,
  инопланетный лес), Lumen для отражённого света от цветного неба, туман по
  высоте, погода (пыльные бури, снег, серные гейзеры Ио) через Niagara.
- **Корабль.** Модульный Nanite-корпус (панели, радиаторы, антенны),
  эмиссивные полосы и навигационные огни, Niagara-выхлоп, меняющий цвет и
  длину от тяги и форсажа, кабина с голографическим HUD (UMG в мире),
  щит как френелевский материал, который вспыхивает при попадании. Три
  корпуса из редактора корабля (`menu.ts`) становятся тремя пресетами модулей.

## 6. Диалоги: почему повторяются и что делать

Почему повторяются (по `universe/game/dialogue.ts`):
- у сценарного разговора жёсткий скелет: приветствие → история → вопрос →
  слух → беда → поручение, одинаковый у всех существ;
- общие пулы маленькие: 10 историй, 12 слухов, 8 вопросов, по 5 вариантов
  ответа пилота на шаг и тон. После нескольких разговоров игрок видел всё;
- память «уже рассказано» (`told`) хранит последние 12 реплик и только
  у одного существа, поэтому другое существо рассказывает те же слухи;
- LLM-режим работает только с ключом игрока, а без него всегда включается сценарий.

Решение по нарастанию стоимости:
1. **Грамматика вместо готовых фраз (0 токенов).** Реплики собираются из
   шаблонов со слотами (в духе Tracery), а слоты заполняются фактами мира:
   настоящими телами системы, данными каталога («у WASP-76 b ночью идёт
   железный дождь, там за тысячу кельвинов»), событиями самого игрока
   («ты сбил трёх перехватчиков у Ганимеда»), погодой и временем суток.
   Число сочетаний на порядки больше, чем готовых строк.
2. **Общая память мира.** Рассказанное помнит не одно существо, а весь мир.
   Слухи распространяются: что пилот сделал в одной системе, в другой
   пересказывают с искажениями.
3. **Разговор как граф намерений, а не фиксированные 5 шагов.** Существо
   выбирает тему по характеру, настроению и тому, что игрок ещё не слышал.
   Поручение появляется, когда оно уместно, а не на 5-м шаге.
4. **Банк реплик, сгенерированный один раз.** Разовый офлайн-прогон LLM
   (один скрипт, копейки) создаёт тысячи реплик по ключу
   «вид × тема × настроение» → DataTable. В игре — ноль запросов.
5. **Живая LLM по желанию игрока** (как сейчас, свой ключ) или локальная
   модель в самой игре (плагины для llama.cpp/ONNX) — без облака и без
   оплаты за токены. Ответ модели проходит ту же проверку `sanitizeQuest`,
   чтобы поручение всегда было выполнимым.

Рекомендую сочетание 1 + 2 + 3 как основу, 4 — как наполнение, а 5 оставить опцией.

## 7. Порядок работ

1. Подключить MCP локально и проверить (раздел 1).
2. Создать C++-проект `unreal/UniverseUE`, перенести `physics.ts` и
   `mandelbrot.ts` с тестами: одинаковые сиды → одинаковые системы.
3. Уровень системы: звезда, планеты на орбитах, Sky Atmosphere, небо из каталога.
4. Корабль и полёт, затем порталы (раздел 4).
5. Посадка: Landscape + PCG-биомы.
6. Бой, миссии, прогресс, существа, новая система диалогов.
